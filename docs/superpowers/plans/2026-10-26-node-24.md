# Node 24 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every Node the project installs or builds with from 22 to 24, and move the GitHub Actions to their Node-24 majors (eggie-resources#60).

**Architecture:** The VM's Node comes from NodeSource in `runtime/install/install.sh`; its floor `NODE_MIN` becomes 24 and the apt repo is derived from it, so they can't disagree. The web console's `engines` and `@types/node` follow 24 (its image already builds on `node:24-alpine`). Both workflows move to the latest action majors, all `runs.using: node24`.

**Tech Stack:** bash, NodeSource apt, npm workspace (Vite/Vitest/TS), GitHub Actions.

**Spec:** none written — decisions taken with the user (2026-10-26):
- Upgrade everything to Node 24; no backward compatibility, no migration path.
- Actions to latest majors: `actions/checkout@v7`, `actions/setup-python@v7`, `actions/setup-node@v7`, `actions/upload-artifact@v7`, `actions/download-artifact@v8`, `docker/setup-qemu-action@v4`, `docker/setup-buildx-action@v4`, `docker/login-action@v4`; web tests `node-version: "24"`.
- Web: `engines.node` `>=24`, `@types/node` `24.19.2` (exact pin, like the other devDependencies).

## Global Constraints

- `NODE_MIN=24.0.0` in `install.sh`; the NodeSource line reads `node_${NODE_MIN%%.*}.x`.
- Checked already: `skills@1.5.26` (the only thing run on the VM's Node; deps `tar`, `yaml`, engines `>=22.20.0`) runs on Node 24; web `npm test` (280), `typecheck`, `build` pass on Node 24.15.
- Comments: short, no ticket references (user's CLAUDE.md).

## Review Focus

1. An existing VM with NodeSource 22 re-runs install: `node_ok` fails on 22.x < 24.0.0, the list file is overwritten to `node_24.x`, `apt-get install -y nodejs` upgrades. Covered only by the live-VM run (network); no unit test, per `runtime/install/CLAUDE.md`.
2. `@types/node` 24 exposes fewer APIs than 26: `npm run typecheck` must still pass.
3. `setup-node@v6+` limits automatic caching to npm — our explicit `cache: npm` + `cache-dependency-path` must stay.
4. `download-artifact@v8` errors on digest mismatch by default and skips unzipping non-zipped artifacts — our uploads are zipped by default (`archive` not set), so `pattern` + `merge-multiple` behaves as before.
5. Error messages in `install.sh` still say "Node.js 22" — must name the new major.
